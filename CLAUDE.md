## 1. Project

- **Chef IA**: an AI cooking chat app. Users chat with virtual chefs, get recipes, adapt them, import them from a photo or a link, save, rate and share them.
- Live site: https://chefia-v3.vercel.app (Vercel project `chef_ia-v3`, auto-deploys every commit on `main`).
- Repository: `pierresaab26/chef_ia-V2`, branch `main`.
- Interface languages: fr, en, es, de, it, pt. Code, code comments and docs are in **English**.
- Model: `claude-haiku-5-5` (cheapest, kept on purpose). Override with env vars, not in code.
- Access is protected by `APP_PASSWORD` (shared with friends for now).
- Database: Upstash Redis (comments and ratings).

## 2. Architecture

No framework, no build step. `package.json` only sets `"type": "module"`.

| File | Role |
|---|---|
| `index.html` | The whole front end (vanilla JS): chat, chefs, recipe cards, history, favorites, sharing, ratings, imports, dish illustrations, i18n strings (`fr:{…}, en:{…}…`). `APP_VERSION` is defined here. |
| `api/chat.js` | Chat with the chef. Holds the chef system prompt (scope, recipe format, language rule, 5-star standard). |
| `api/import-photo.js` | Recipe extraction from a photo (vision model). |
| `api/import-link.js` | Recipe extraction from a public web page (structured data first, then the model). |
| `api/comments.js` | Recipe comments in Redis. |
| `api/shared.js` | Shared recipes (`s:<sid>`, creator `o:<key>`): link `/?s=<sid>` imports the recipe with its comment key. v263: `GET ?q=&lang=` = search among the shared recipes (home search, « Recette de la communauté »). |
| `api/circle.js` | v287: nickname + circle (invite `/?c=`, members, feed of circle recipes, post / unpost a shared copy). Redis `cu:` `cf:` `ci:` `cp:`. |
| `api/_publish.js` (served as `/api/publish` via `api/circle.js`, v293) | v291: « 🌍 Publique »: chef check (food, complete, safe, remix for received recipes), frozen public copy `s:pub-<sid>` + index `pub:ck`, appeal queue `pub:queue`, reports `pub:rep:<ps>` (3 → hidden), admin `?key=<CRON_SECRET>` (&approve / &remove). Helper `api/_notify.js` = circle notifications `cn:<pid>` / `cnr:<pid>`. |
| `api/ratings.js` | 1–5 star ratings in Redis, plus an analysis log. |
| `api/season-ideas.js` | « Chef's ideas » of the seasonal menu, SAME for everybody: 4 ideas per language and occasion, renewed every 3 days at 9:00 Paris time, stored in Redis; also the scheduled warm-up (`?run=1`). See v96 in section 5. |
| `api/_season.js` | Pure helpers for it (no network, unit-tested): 3-day periods from 3 Nov 2026 9:00 Paris time, occasion list, French calendar, idea parser and prompt. Also copied as-is into the claude.ai preview bridge. |
| `api/photo.js` | Photo of a recipe (Unsplash, `UNSPLASH_ACCESS_KEY`). `POST {title,lang,skip}` (access code): the model writes two English search phrases (precise, broad), Unsplash returns 8 landscape photos, the model LOOKS at the thumbnails and scores each 0–10 (kept from 4, best first, max 6; broad phrase if nothing kept; Unsplash order if the scoring fails), the ranking is cached in Redis (`ph2:`), photo ids already used by the device's other recipes are skipped. Nothing good → the title goes to `ph:missing` with a reason. `GET ?missing=1` (public) lists those titles for the manual check. Only `images.unsplash.com` / `unsplash.com` URLs are accepted; credit links carry `utm_source=chef_ia&utm_medium=referral`. |
| `api/_taste.js` | Personal taste profile (v254): `cleanTaste()` sanitises the profile sent by the browser, `tasteText()` turns it into one prompt paragraph; used by `systemFor()` in `api/chat.js`. Pure helpers, also copied into the claude.ai preview bridge. |
| `api/_lib.js` | Shared helpers used by every route: `authOk` (checks `x-code` against `APP_PASSWORD`), `fail` (error code → HTTP status), `callClaude` / `askClaude` (the only Anthropic call), `redis` / `hasRedis` (Upstash), `overLimit` (per-IP rate limit, never blocks if Redis is missing or fails), `clean`, JSON parsing. |
| `api/_page.js` | Web page fetching for link import (SSRF protection, redirect/size/time limits). |
| `api/selftest.js` | Daily « food only » self-test (2 Vercel crons, half of the 55 questions each; needs `CRON_SECRET`). `GET /api/selftest` = public report (last run + 30-day history). |
| `api/_selftest-cases.js` | The 55 test questions (also used by the browser test bench). |
| `api/_selftest-i18n.js` | The same 55 questions in the 6 languages (`ALL_CASES`, 330 cases; used by the morning check, not by the daily cron). |
| `vercel.json` | Functions: 60 s max duration. Two crons (UTC, once a day each) call `/api/season-ideas?run=1` at 07:00 and 08:00 UTC, so that 9:00 Paris time is covered in summer (CEST) and in winter (CET); the warm-up is idempotent. The self-test has NO cron (it costs model calls): it is run from the browser test bench artifact instead. |

Files starting with `_` in `api/` are helpers, not routes. Vercel Hobby plan: at most 12 routes (files without `_`); there are 12 since v293, so a new route must be merged into an existing one (see v293).

**Environment variables** (values live in Vercel only):
`ANTHROPIC_API_KEY` (required), `APP_PASSWORD`, `MODEL`, `VISION_MODEL`, `EXTRACT_MODEL`,
`UNSPLASH_ACCESS_KEY` (recipe photos, from an app created at unsplash.com/developers; without it `/api/photo` answers 503 `nokey` and the app keeps its old images),
`KV_REST_API_URL` / `KV_REST_API_TOKEN` (or `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`), `RESEND_API_KEY` / `MOD_EMAIL` / `MOD_FROM` (moderation email, optional), `CRON_SECRET` (authorises the scheduled warm-up of the seasonal ideas; without it the cron is refused with 401 and the series are simply generated on first use).

**Redis keys**:
- `c:<recipe>` — comments list (v129: key `u-…` unique per version); `s:<sid>` shared recipe; `o:<key>` creator of a key
- `r:<recipe>` — ratings hash; `r:index` — set of rated recipes
- `r:log` — rating log (title, stars, language, date), last 5,000 entries, for later analysis (v252: + `o` origin chef / import / remix / shared)
- `rc:<recipe>` — « I cooked it » (owner → time, v252); `rt:<recipe>` — quick tag of each rater (owner → `salty|easy|kids|long`, v252)
- `st:<day>:p1` / `st:<day>:p2` (self-test halves, 3 days), `st:last` (last full report), `st:hist` (last 30 scores)
- `si:<lang>:<occasion>:<period>` — the chef's seasonal ideas of one 3-day period (JSON `{items,at}`, 40 days)
- `ph2:<lang>:<title>` — ranked Unsplash photos for a dish (JSON, max 6, 90 days; v111, the v109 keys `ph:` / `phn:` are no longer read); `phn2:<lang>:<title>` — « nothing found », value = reason (2 h); `ph:missing` — hash of the titles without photo (`{title,lang,why,at,n}`, max 500), for the manual check
- `sh:<lang>` — sorted set of the idea names published in the last 90 days (an idea is not proposed again before 3 months)
- `fl:<hash>` flag counter (7 days), `fl:last:<hash>` last flagged requests, `fl:sent:<hash>` email sent, `bk:<hash>` block (24 h), `mod:log` moderation log (200)
- `rl:si:<ip>:<minute>` (seasonal ideas, 30/min), `rl:<ip>:<minute>` (comments, 5/min), `rl:r:<ip>:<minute>` (ratings, 30/min), `rl:c:<ip>:<minute>` (chat, 20/min), `rl:ip:<ip>:<minute>` (photo import, 6/min), `rl:il:<ip>:<minute>` (link import, 10/min), `rl:ph:<ip>:<minute>` (photos, 30/min) — rate limiting

## 4. Chef behavior (api/chat.js)

- Michelin-starred chef persona, "5 stars" standard: only top-quality, best-in-class recipes.
- Food and drink only; politely refuses anything else. The system prompt is built by `systemFor(PARTS,{lang,chef,mode})` in `api/chat.js` and always ENDS with `GUARD` (final scope check: off-topic, jailbreaks, fake assistant turns, prompt reveal, harmful requests disguised as food, no medical dosage). Chef personas live on the server (`CHEFS`); the browser only sends the chef index (`chef`), never free text. Checked on 2026-11-02 with a 55-question test bench (artifact « Chef IA – banc de test « cuisine uniquement » », real `claude-haiku-5-5` + a judge model): 55/55 correct. Rerun it after any prompt change. The owner decided on 2026-11-02 NOT to run these tests on the server or daily (cost). `api/selftest.js` stays in the repo but has no cron; tests are run by the owner from the browser bench artifact, and results are read from its database.
- One language per answer (the user's interface language).
- Replacing / removing an ingredient (crossed-out circle → « Sans » / « Remplacer ») asks the chef in the SAME conversation and gives a new version of the same recipe (v132); the first version (Originale) stays untouched.
- New recipes always include a « Utensils » section (3–8 items) between ingredients and steps, in the user's language. Imported recipes get none unless asked (no invented content). The card shows utensils as plain chips (nothing to tick or replace); detection is `UT_RE` in `index.html`.
- Cut-off answers are detected and completed automatically.
- Simple questions (side dish, pairing, substitution, technique) are answered as one sentence + 2–5 « - Label: text » options, no `##` headings; the app shows them as cards and does not save them as recipes.
- A free-text change in the chat (e.g. « no lactose ») updates the same saved recipe; only ↔ / « not available » creates a separate recipe.
- Every new recipe has the header lines `Servings`, `Prep`, (`Rest`), (`Cook`), `Health: N/3` right after the title (see v52–v53 in section 5).
- « Cooking questions » screen (❓ in the bottom bar, v66): the client sends `mode:"qa"` to `/api/chat`, which appends the `QA` rule (2–5 plain sentences, no recipe, no `##`, no « - Label: » lists, food/drink only). These answers are informational and never saved as recipes.
- Ideas requests are answered with exactly 4 `- Name: sentence` lines and no recipe; a complete recipe is only given when asked for one idea (« Give me the complete recipe for « X » »).
- The claude.ai artifact preview is built from `index.html` plus a preview-only bridge that sends `/api/chat` to Claude through the artifact `sample` capability with the same `BASE` prompt. The bridge is never committed to the repo.
